# M08: 星型模型仓库 — DuckDB 作为 "Redshift"

## 学习目标

- 维度建模：事实表、维度表、星型模型
- 如何在实现前定义事实粒度
- 代理键 vs 自然键
- 缓慢变化维度（SCD）概念
- 参照完整性和粒度唯一性检查

## 概述

数据仓库提供了精选的、业务友好的分析模型。与湖（直接对原始 Parquet 编写任意 SQL）不同，仓库具有显式的表、关系和约束。

## 核心概念

### 1. 事实粒度

**粒度**是事实表中的原子详细级别。每行代表该粒度下的一个度量。

**我们的粒度**：每个 **content + region + device + date** 一行。这意味着每个组合每天只有一行。SUM、AVG 等聚合在此粒度下有意义。不会因为以错误粒度连接而意外重复计算。

**在写任何代码之前始终定义粒度。**

### 2. 代理键

自然键来自源系统。代理键是仓库生成的 INTEGER。INTEGER 连接比 VARCHAR 更快。源系统键可能变化——代理键隔离仓库。SCD 处理：新代理键跟踪同一自然键的新版本。

### 3. 星型 vs 雪花

星型（非规范化）：维度包含所有列。更快的查询，一些冗余。雪花（规范化）：维度拆分为子维度。无冗余，更多连接。我们使用星型模型，因为分析查询受益于更少的连接。

### 4. 缓慢变化维度

当内容项的类型从 "Drama" 变为 "Comedy" 时：
- **SCD Type 1**：覆写（丢失历史）— 我们使用此类型
- **SCD Type 2**：添加新行和新代理键（保留历史）
