# M01: 合成数据生成器

## 学习目标

- 如何设计模拟真实世界分布的合成数据集
- 为什么确定性随机种子对可复现的基准测试至关重要
- 如何有意注入数据质量问题（重复、畸形行、迟到事件）
- 内容流行度的幂律分布建模

## 概述

在任何 ETL 管道运行之前，它需要数据。在生产环境中，数据来自真实的用户事件——页面浏览、视频播放、购买点击。但对于学习项目，我们生成与真实数据行为类似的合成数据。

本模块创建三个数据集：

## 核心概念

### 1. 内容流行度的幂律分布

真实的内容平台遵循幂律分布：少数标题获得大量观看（"头部"），而大多数标题获得很少（"长尾"）。我们使用类似 Zipf 的权重来建模：

```
流行度权重 = 1 / (排名 ^ 0.8)

排名 1:   权重 = 1.000  (最受欢迎)
排名 10:  权重 = 0.158
排名 100: 权重 = 0.025
排名 1000: 权重 = 0.004 (最不受欢迎)
```

这意味着头部内容获得的事件量大约是尾部内容的 250 倍。在 M03 中分析数据倾斜时可以观察到此现象。

### 2. 数据质量注入

真实数据是混乱的。我们有意注入三种类型的问题：

| 问题 | 比例 | 方式 |
|------|------|------|
| **重复** | 0.25% | 复制已有 event_id 并使用略不同的时间戳 |
| **畸形** | 0.07% | 无效地区（"XX"）、超出范围的完成率（-0.5, 1.5）、错误时间戳 |
| **迟到事件** | 0.42% | 时间戳在过去 3–7 天的事件 |

这些给了 ETL 管道（M02–M06）真实的处理场景——验证失败、去重工作和迟到数据处理。

### 3. 确定性可复现性

相同种子 → 相同数据。每次都一样。这对以下方面至关重要：
- **基准测试**：M05 中的 CSV 与 Parquet 对比必须使用相同数据
- **CI**：测试始终通过，不会出现不稳定性
- **调试**：可以重新生成完全相同的数据集来复现问题

## 演练

```bash
# 小规模（快速迭代，1万行）
uv run python -m etl_playground.m01_data_generator.exercise --scale 10000

# 默认规模（50万行 — 约 3 秒）
uv run python -m etl_playground.m01_data_generator.exercise

# 基准测试规模（500万行 — 约 30 秒，需要 4GB+ RAM）
uv run python -m etl_playground.m01_data_generator.exercise --scale 5000000
```

生成器输出：
```
data/raw/
├── viewing_events/ingest_date=2026-08-12/events.csv    (~62 MB for 500K)
├── content_metadata/metadata.csv                       (~0.1 MB, 1000 rows)
└── content_launch/launch.csv                           (~0.2 MB, 4000 rows)
```

## 常见陷阱

- **规模 vs 内存**：2000 万行需要约 8GB RAM。从小规模开始。
- **CI 中的随机种子**：CI 集成通道使用 `--scale 10000` 以提高速度。
- **ingest_date 分区**：原始数据按生成日期组织，而非事件日期。这模拟了每日批量上传。
